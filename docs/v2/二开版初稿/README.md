## 3. 与旧版文档的关系

本目录不是简单复制旧版文档，而是在旧版基础上做了以下统一修正：

1. 设备端 UI 渲染方式
   - 旧需求中曾写“所有 UI 图形都用 HTML 画”
   - 二开版改为：
     - 设备端页面使用 `LVGL`
     - 浏览器配网页面使用 `HTML`
   - 这样才与当前项目架构和后续代码实现保持一致

2. 硬件按钮认知
   - 文档目标仍然保留“三个物理按键”的交互模式
   - 但二开版明确区分：
     - 硬件板上存在 `BOOT / PWR / KEY`
     - 当前代码仅接入了 `BOOT`
     - 其余两个按钮需要在板级代码中继续补齐映射

3. 配网模式定义
   - 二开版采用“设备屏配网首屏 + 浏览器四步配置”的双层方案
   - 不再把设备端页面和网页配置页混成同一套实现

4. 激活流程定义
   - 二开版保留现有 `Application + Ota` 的联网后激活主干
   - 在此基础上新增“绑定码展示页”的交互设计

5. 现状基线沉淀
   - 将原始的代码分析内容收敛为 `00-现状基线分析.md`
   - 原始分析稿保留在 `docs/v2/` 根目录，作为历史参考，不再作为正式初稿的一部分参与后续收敛

## 5. 文档职责边界

为避免多份文档重复表达同一件事，后续统一按以下边界使用：

| 文档 | 主要回答什么 | 不负责什么 |
|------|--------------|-----------|
| `00-现状基线分析.md` | 当前代码事实、已实现能力、主要缺口、稳定约束 | 不负责定义目标页面长什么样，也不负责安排详细开发步骤 |
| `01-二开需求初稿.md` | 版本目标、功能范围、验收口径、用户与业务诉求 | 不负责页面像素布局，不负责具体代码落点 |
| `02-二开原型说明初稿.md` | 页面清单、页面流转、设备页与网页页关系、原型结构 | 不负责最终视觉规范，不负责具体代码架构 |
| `03-二开UI设计初稿.md` | 视觉规范、固定像素建议、字体/图标/组件规则 | 不负责业务流程定义，不负责代码模块拆分 |
| `04-二开概要设计初稿.md` | 模块职责、状态拆分、代码落点、实现边界 | 不负责逐页视觉细节，不负责开发执行节奏 |
| `05-第一阶段代码设计-配网首屏.md` | 第一阶段最小改动方案与配网首屏专项设计 | 不负责完整多页面体系与全局开发路线 |
| `06-整体设计与原型落地方案.md` | 总体收敛方式、原型验收顺序、开发准入与分阶段执行 | 不负责替代 `04` 的代码入口细节，也不负责替代 `03` 的视觉规范 |

### 5.1 使用原则

后续讨论时统一按以下顺序取证：

1. 先看 `00`
   - 确认当前代码事实和约束
2. 再看 `01`
   - 确认产品目标和验收范围
3. 再看 `02` 与 `03`
   - 确认页面流转和视觉规范
4. 再看 `04`
   - 确认代码落点和模块职责
5. 再看 `05` 或 `06`
   - 确认专项方案或整体推进顺序

### 5.2 冲突处理原则

如果多份文档出现表述重叠，统一按以下优先级理解：

1. 现状事实以 `00` 为准
2. 产品目标与验收口径以 `01` 为准
3. 页面流转以 `02` 为准
4. 视觉规范以 `03` 为准
5. 代码落点以 `04` 为准
6. 第一阶段专项以 `05` 为准
7. 开发收敛顺序以 `06` 为准
