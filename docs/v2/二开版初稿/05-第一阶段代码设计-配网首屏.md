## 1. 文档目标

本文档用于定义第一阶段的代码设计方案。

第一阶段只聚焦一个目标：

- 在 `waveshare-esp32-s3-rlcd-4.2` 上实现独立的设备端配网首屏

本阶段不直接进入四步网页配网，也不进入主页、多页面和三按键完整接入。

---

## 2. 第一阶段范围

### 2.1 本阶段必须完成

1. 开机无历史 WiFi 时，设备进入配网模式
2. 屏幕显示独立的“首次配网”页面
3. 页面显示热点 SSID 和访问地址
4. 页面使用中文文案
5. 页面适配 `400 x 300` RLCD 屏幕
6. 顶部状态区域不被主体内容遮挡
7. 首次配网页顶部不显示 WiFi 图标
8. 配网成功或退出配网后可隐藏该页面

### 2.2 本阶段暂不强制完成

1. 四步网页配网服务
2. 激活页
3. 首页 / 音乐 / 课程表 / 天气页
4. 三个物理按键完整映射
5. 温湿度在顶部的最终展示方案

说明：

- 温度接口当前已有 `Board::GetTemperature(float&)`
- 湿度接口当前公共层没有现成抽象
- 为了保证第一阶段最小改动闭环，本阶段先不把温湿度接入当成阻塞项

## 3. 当前代码链路

### 3.1 当前真实流程

当前配网入口在：

- [wifi_board.cc](file:///Users/zuxingyu/Documents/workspace/esp/feifeiAssistant/main/boards/common/wifi_board.cc)

关键调用链如下：

```text
Application::Initialize()
  ↓
Board::StartNetwork()
  ↓
WifiBoard::StartNetwork()
  ↓
WifiBoard::TryWifiConnect()
  ↓
无历史 WiFi
  ↓

  ↓
wifi_manager.StartConfigAp()
  ↓
Application::Alert(...)
  ↓
Display::SetStatus / SetEmotion / SetChatMessage
```

### 3.2 当前问题

当前实现的问题不是“没有进入配网”，而是“进入配网后只显示一条通用提示”。

具体问题有：

1. 当前没有独立的配网首屏接口
2. `StartWifiConfigMode()` 只调用 `Application::Alert(...)`
3. 当前 UI 仍然复用通用聊天界面
4. RLCD 板默认字号较大，容易导致中文字段截断
5. 顶部状态区域和主体布局还没有专门为配网页设计

## 4. 设计原则

### 4.1 保持板级目录主承载

本阶段遵循前面已经确认的原则：

- 板级页面实现优先放在 `main/boards/waveshare/esp32-s3-rlcd-4.2/`
- 公共层只做最小必要修改

### 4.2 最小公共改动闭环

虽然页面本身放在板级目录中实现，但 `wifi_board.cc` 位于公共层，需要通过 `Display*` 调用配网页。

因此本阶段允许进行一次很小的公共接口扩展：

- 在 `Display` 基类增加“显示/隐藏配网首屏”接口

这属于必要且可接受的公共改动，因为：

1. 调用方在 `WifiBoard`
2. `WifiBoard` 只持有 `Display*`
3. 不增加该接口，就只能把公共配网逻辑反向依赖到板级类，不利于结构稳定

### 4.3 页面实现放在本板显示类

独立配网页的对象、排版和可见性控制，优先放在：

- `custom_lcd_display.h`
- `custom_lcd_display.cc`

而不是先改造成新的公共页面框架。

## 6. 接口设计

### 6.1 `Display` 基类新增接口

建议在 `display.h` 增加：

```cpp
virtual void ShowWifiConfigPage(const char* ssid, const char* url);
virtual void HideWifiConfigPage();
```

默认实现放在 `display.cc`：

```cpp
void Display::ShowWifiConfigPage(const char* ssid, const char* url) {
    ESP_LOGI(TAG, "ShowWifiConfigPage: ssid=%s, url=%s", ssid ? ssid : "", url ? url : "");
}

void Display::HideWifiConfigPage() {
}
```

设计理由：

- 对无屏设备或未实现该能力的板型，保持 no-op
- 对本板型，由 `CustomLcdDisplay` 重写即可

### 6.2 `CustomLcdDisplay` 新增接口

建议在 `custom_lcd_display.h` 中声明重写：

```cpp
virtual void ShowWifiConfigPage(const char* ssid, const char* url) override;
virtual void HideWifiConfigPage() override;
```

并新增用于首屏的 LVGL 对象指针，例如：

```cpp
lv_obj_t* wifi_config_page_ = nullptr;
lv_obj_t* wifi_title_label_ = nullptr;
lv_obj_t* wifi_ssid_label_ = nullptr;
lv_obj_t* wifi_ssid_value_label_ = nullptr;
lv_obj_t* wifi_url_label_ = nullptr;
lv_obj_t* wifi_url_value_label_ = nullptr;
lv_obj_t* wifi_hint_label_ = nullptr;
lv_obj_t* wifi_waiting_label_ = nullptr;
lv_obj_t* wifi_top_info_label_ = nullptr;
bool wifi_config_page_visible_ = false;
```

说明：

- 不建议把这些字段放回 `LcdDisplay`
- 因为当前需求明确是本板二开优先

## 7. 页面布局设计

### 7.1 顶部区域

本阶段页面顶部遵循以下规则：

- 不显示 WiFi 图标
- 保留电池图标
- 可保留充电状态
- 当前阶段不把湿度接入做成阻塞项

实现建议：

1. 当配网页显示时，隐藏 `network_label_`
2. 保留 `battery_label_`
3. `mute_label_` 默认可隐藏
4. `status_label_` 和 `notification_label_` 视情况隐藏，避免压住主体内容

这样可以在不重构公共状态栏的情况下，快速满足“配网页顶部不显示 WiFi”。

### 7.2 页面主体

建议结构如下：

```text
┌────────────────────────────────────┐
│ 顶部状态区：无 WiFi，仅电池/充电    │
├────────────────────────────────────┤
│            配网图标                │
│            首次配网                │
│                                    │
│  WiFi名称                          │
│  XZ-Setup-XXXX                     │
│                                    │
│  访问地址                          │
│  192.168.4.1                       │
│                                    │
│  请先连接上方热点，再在浏览器中     │
│  打开访问地址完成配置              │
├────────────────────────────────────┤
│            等待连接中...           │
└────────────────────────────────────┘
```

### 7.3 排版策略

为避免当前默认大字号造成截断，配网页建议使用以下策略：

1. 标签和值分两行显示
2. SSID 和 URL 使用单独值行
3. 值标签宽度设为页面可用宽度
4. 长文本启用滚动或省略
5. 标题和提示区减少上下间距

## 8. `wifi_board.cc` 改造设计

### 8.1 进入配网模式

当前 `StartWifiConfigMode()` 中，在 `wifi_manager.StartConfigAp()` 后，建议把现有 `Alert()` 逻辑调整为：

```cpp
Application::GetInstance().Schedule([&wifi_manager]() {
    auto display = Board::GetInstance().GetDisplay();
    const std::string ssid = wifi_manager.GetApSsid();
    const std::string url = wifi_manager.GetApWebUrl();

    if (display != nullptr) {
        display->ShowWifiConfigPage(ssid.c_str(), url.c_str());
        display->UpdateStatusBar(true);
    }

    std::string hint = Lang::Strings::CONNECT_TO_HOTSPOT;
    hint += ssid;
    hint += Lang::Strings::ACCESS_VIA_BROWSER;
    hint += url;

    Application::GetInstance().Alert(
        Lang::Strings::WIFI_CONFIG_MODE,
        hint.c_str(),
        "gear",
        Lang::Sounds::OGG_WIFICONFIG
    );
});
```

设计说明：

- 配网页负责“视觉主界面”
- `Alert()` 保留为语音和通用兜底提示
- `UpdateStatusBar(true)` 用于立即刷新电池和网络状态

### 8.2 退出配网模式

建议在以下事件中隐藏配网页：

- `NetworkEvent::Connected`
- `NetworkEvent::WifiConfigModeExit`

设计方式：

```cpp
auto display = Board::GetInstance().GetDisplay();
if (display != nullptr) {
    display->HideWifiConfigPage();
    display->UpdateStatusBar(true);
}
```

这样可保证：

- 配网成功后页面及时消失
- 配网退出后页面不残留

## 9. `CustomLcdDisplay` 改造设计

### 9.1 页面创建时机

建议懒创建：

- 第一次调用 `ShowWifiConfigPage()` 时创建对象
- 后续仅更新文字和显隐

理由：

- 不打扰现有 `SetupUI()`
- 不增加开机阶段无关对象

### 9.2 页面对象挂载方式

建议将 `wifi_config_page_` 挂在当前 `screen` 上，并位于现有内容层之上。

建议行为：

1. 隐藏通用主体内容：
   - `content_`
   - `emoji_box_`
   - `preview_image_`
   - `bottom_bar_`
2. 不隐藏顶部状态相关对象
3. 把 `wifi_config_page_` 移到前景

### 9.3 页面显隐策略

#### 显示时

- 更新 SSID 文本
- 更新 URL 文本
- 隐藏不需要的通用内容
- 隐藏 `network_label_`
- 根据需要隐藏 `mute_label_`
- 保留 `battery_label_`

#### 隐藏时

- 隐藏 `wifi_config_page_`
- 恢复 `emoji_box_` 或默认中间内容
- 恢复 `network_label_`
- 恢复原有状态栏行为

### 9.4 不建议的做法

本阶段不建议：

1. 在 `LcdDisplay::SetupUI()` 里硬编码配网页对象
2. 直接隐藏整个 `top_bar_` 或 `status_bar_`
3. 在 `wifi_board.cc` 中写 LVGL 细节
4. 为第一阶段先引入新的页面管理器

## 10. 推荐方法拆分

### 10.1 `custom_lcd_display.h`

建议新增的方法：

```cpp
void EnsureWifiConfigPageCreated();
void UpdateWifiConfigPageText(const char* ssid, const char* url);
void SetWifiConfigStatusBarVisibleState(bool visible);
```

### 10.2 `custom_lcd_display.cc`

建议新增的方法组织如下：

```cpp
void CustomLcdDisplay::ShowWifiConfigPage(const char* ssid, const char* url);
void CustomLcdDisplay::HideWifiConfigPage();
void CustomLcdDisplay::EnsureWifiConfigPageCreated();
void CustomLcdDisplay::UpdateWifiConfigPageText(const char* ssid, const char* url);
void CustomLcdDisplay::SetWifiConfigStatusBarVisibleState(bool visible);
```

设计意图：

- `Show/Hide` 负责外部调用
- `Ensure...` 负责懒创建
- `Update...` 负责文本刷新
- `Set...VisibleState` 负责切换顶部状态区域的局部显示规则

## 11. 本阶段不做的事情

### 11.1 不新增页面管理框架

本阶段只做一个页面，不需要先建立多页面系统。

### 11.2 不重构公共状态栏架构

本阶段只需要做到：

- 顶部不显示 WiFi
- 主体不遮挡顶部
- 电池仍然可见

不需要在这一阶段完整重写 `LvglDisplay::UpdateStatusBar()`

### 11.3 不接入完整温湿度方案

虽然板上有 `SHTC3`，但当前公共层没有湿度接口。

为了遵守“最小修改闭环”，第一阶段先不把温湿度读数接入作为交付阻塞项。

若后续确认要做，可在第二阶段或第一阶段增强版中增加：

- 板级温湿度读取
- 页面顶部定制显示

## 12. 验收标准

第一阶段完成后，至少应满足以下验收条件：

1. 清空 WiFi 后开机，设备可进入独立配网首屏
2. 屏幕可显示中文标题、热点 SSID 和访问地址
3. `WiFi名称`、`访问地址` 不被大字号截断
4. 顶部状态区域仍然存在
5. 顶部不显示 WiFi 图标
6. 电池图标可见
7. 配网成功或退出后页面可隐藏
8. 不影响现有 `Alert()` 兜底提示链路
